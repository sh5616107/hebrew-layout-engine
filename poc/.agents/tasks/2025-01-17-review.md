# POC Review: Vivliostyle vs Typst Hebrew Layout Engines

The POC evaluates two existing layout engines against 13 requirements for Hebrew religious book typography. Both engines produced PDFs with visual evidence (PNG files), and RESULTS.md documents the findings. The work is honest about limitations and provides a data-driven recommendation.

**Watch for:** Missing opening window implementation (confirmed), Typst footnotes rendering per-column instead of full-width (confirmed architectural limitation), determinism failing due to PDF metadata timestamps (not a layout issue), TOC page numbers missing in both engines.

**Verdict**: APPROVED

## High-level view

Sample data covers Genesis 1 with authentic Hebrew text including nikud and teamim marks, structured as a multi-page document (3 pages for Vivliostyle, 2 for Typst) with TOC, headings, footnotes including one long note, and opening-word formatting. Visual evidence exists for all pages as PNG files.

Both engines handle B5 page size, Hebrew RTL text flow, nikud rendering, and two-column layout correctly. Column balancing passes on Vivliostyle's final page; Typst's output doesn't have a partial final page to test. Baseline grid alignment appears correct in both engines based on visual inspection, contrary to expectations from GitHub issues.

Vivliostyle's footnote system works: full-width placement below both columns, separator line visible, same-page placement, and continuation across pages all confirmed. Typst places footnotes at the bottom of each column independently—a confirmed architectural limitation documented in their forum.

Opening window (empty space below bold opening words) fails in both engines. Vivliostyle shows bold text but no window; Typst's implementation is broken. Last-line centering is partial in Vivliostyle (some lines centered, not consistently applied) and absent in Typst. Running headers differ between odd/even pages with gematria numbering in both engines, though Typst's differentiation is less pronounced in the 2-page sample.

TOC entries appear in both outputs but without page numbers—neither engine's adapter successfully implemented the cross-reference mechanism. Determinism fails in both due to PDF metadata timestamps, not layout variance.

RESULTS.md provides honest assessments with PNG file references, estimates workaround complexity (500-800 LOC for Vivliostyle, 800-1200 LOC for Typst), and recommends building a custom engine based on the data. Adapters read sample.json and generate engine-specific output without modifying the input.

## Opening window implementation gap

Block-2 in sample.json specifies `"opening": {"words": 3, "bold": true, "windowLines": 2}` to test bold opening words with empty space below. Vivliostyle's output (page 2) shows bold text for the first three words but no window. Typst's output shows no window effect. Both correctly identified as FAIL in requirements matrix.

The adapters contain implementation attempts: to-html-css.js wraps opening words in a span with data attribute; to-typst.js uses place() with float. Neither produces the required rectangular void below the bold text. RESULTS.md estimates 150-250 LOC workaround for Vivliostyle (shape-outside CSS) and 100-200 LOC for Typst (wrap-it package or manual paragraph construction).

Typst's headers present on both pages with content, gematria function in to-typst.js includes טו/טז handling, but odd/even differentiation less visible in 2-page sample. RESULTS.md marks this PARTIAL—fair assessment given limited sample.

## Last-line centering gap

Requirement (g) asks for only the final line of each paragraph to be centered, other lines justified. Vivliostyle's to-html-css.js applies `text-align-last: center` on paragraph styles. RESULTS.md reports PARTIAL: some last lines appear centered on pages 2-3, but not consistently applied. Issue noted: may center lines that break mid-column, not just true paragraph ends.

Typst has no text-align-last equivalent. To-typst.js defines `centered-last-par` function but doesn't implement it (comment notes Typst lacks ::last-line selector). RESULTS.md marks FAIL with 150-300 LOC workaround estimate for custom show rule. Honest assessment of Typst's limitation.

## TOC without page numbers

Both engines' TOC sections list entries but show no page numbers. Vivliostyle page 1 shows "תוכן העניינים" heading with indented entries for chapter and section names. Typst page 1 (left column) shows similar structure. RESULTS.md identifies both as FAIL.

Root cause for Vivliostyle: CSS `target-counter()` function not working or requires configuration. Root cause for Typst: adapter generates manual TOC entries without using Typst's built-in `#outline()` function. Workaround estimates: 100-200 LOC for Vivliostyle (JavaScript injection), 20-50 LOC adapter fix for Typst (use outline() properly) plus engine limitations. These are reasonable estimates.

## Determinism test methodology

Requirements (m) asks for identical output on repeated runs. Test method: generate PDF twice, compare SHA256 hashes. Both engines: hashes differ, FAIL. RESULTS.md notes PDFs likely contain timestamps or UUIDs in metadata. Workaround: strip metadata before comparison or compare visual content only (50-100 LOC).

The test conflates layout determinism (do line breaks and page breaks happen at the same positions) with PDF file determinism (are the bytes identical). For layout engine evaluation, the relevant question is whether the layout is stable, not whether the PDF container metadata varies. Stripping metadata and re-running would isolate layout behavior. However, RESULTS.md is honest about this and estimates the workaround cost, which is appropriate for POC scope.

## Adapter architecture and engine-agnostic design

Both adapters (to-html-css.js, to-typst.js) read sample.json and transform the document model into engine-specific syntax. Layout logic (opening window, footnote placement, gematria conversion, baseline grid) encoded in sample.json's structure and style definitions, not in engine-specific hacks.

To-html-css.js generates HTML with semantic structure (h1, h2, p tags) and CSS Paged Media rules (@page, @footnote, float: footnote). Opening words wrapped in span with data-window-lines attribute; window creation left incomplete. Footnote references generated as anchor tags with class footnote-ref.

To-typst.js generates .typ markup with #set page(), #set text(), #columns() for layout. Gematria function defined in Typst (not JavaScript) for use in headers. Opening window attempted with place(float: true) but broken. Footnote references use Typst's #footnote[] syntax.

No sample.json modification to work around engine limitations—requirement explicitly prohibited such workarounds. Adapters contain comments documenting limitations (e.g., "TYPST-LIMITATION: Centering only the last line..."). This is good engineering practice for POC.
